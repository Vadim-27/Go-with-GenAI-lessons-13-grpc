===============================================================
LibraTrack — журнал промптів (Тема 13: gRPC замість REST)
===============================================================

Спільний контекст (див. docs/grpc-prompt-kit/00-project-context.md), що додається до всіх промптів:
  * Проєкт: LibraTrack; предметна область — облік примірників книг (Copy: AVAILABLE / BORROWED / LOST);
  * Go, модуль `libratrack`; пакет протоколу `inventory.v1`;
  * кодогенерація: protoc + protoc-gen-go, protoc-gen-go-grpc, protoc-gen-grpc-gateway;
  * клієнти: внутрішні сервіси (gRPC), браузер/зовнішні (REST через gateway);
  * безпека: mTLS між сервісами + JWT користувача в metadata;
  * коментарі й документація — українською.

Постійні правила — docs/grpc-prompt-kit/01-AGENTS-rules-grpc.md.

---------------------------------------------------------------
Приклад промпта (на основі 03-proto-authoring)
---------------------------------------------------------------

  Напиши .proto (proto3) для InventoryService, package inventory.v1,
  go_package "libratrack/gen/inventory":
    - Copy {id, book_id, inventory_number, status}; enum Status з
      STATUS_UNSPECIFIED = 0, AVAILABLE, BORROWED, LOST;
    - unary GetCopy / RegisterCopy / UpdateCopyStatus;
    - server streaming WatchCopyStatus;
    - client streaming BulkRegisterCopies; bidi SyncInventory;
    - HTTP-анотації: GET /v1/copies/{id}, POST /v1/copies, PATCH /v1/copies/{id}/status.
  Поясни рішення щодо номерів полів. Стрімінг-RPC без HTTP-анотацій.

Примітка: повні тексти промптів і шаблони лежать у docs/grpc-prompt-kit/*.md; цей файл лише
фіксує, який промпт для якої частини роботи застосовано.
