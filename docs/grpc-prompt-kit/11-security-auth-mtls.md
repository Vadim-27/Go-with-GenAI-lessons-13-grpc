# 11 · Автентифікація, авторизація, mTLS

> **Коли:** проєктування або аудит безпеки міжсервісних викликів.
> **Результат:** коротка модель загроз, вибір механізмів, реалізація та **матриця негативних тестів**.
> Базова ідея: mTLS автентифікує **сервіс**, токен автентифікує **користувача**, авторизація (ролі) вирішує, **що дозволено**. Це три різні рівні.

````markdown
## Завдання
Розроби й реалізуй захист викликів.

## Що зробити
1. **Модель загроз** (коротко): активи, нападники, 6–10 загроз (підслуховування, підміна сервісу, підробка токена, ескалація ролі, повторне використання токена, обхід через стрімінг, витік через reflection/логи, компрометація сертифіката). Для кожної: чим закрито.
2. **Вибір механізмів і рівнів.** Що дає транспорт (TLS/mTLS), що токен, що авторизація. Якщо mTLS уже забезпечує service mesh, поясни, що лишається на застосунку (авторизація), і не дублюй зайвого.
3. **Транспорт.** TLS не нижче 1.2; для mTLS сервер ВИМАГАЄ і перевіряє клієнтський сертифікат за довіреним CA; клієнт перевіряє сервер. Опиши ротацію сертифікатів і короткі терміни дії. Генерація демо-сертифікатів — лише для локального середовища і окремо від продакшену.
4. **Токени.** Передаються в metadata; перевірка за перевіреною бібліотекою: підпис, дозволений алгоритм (білий список), `exp`, `nbf`, `iss`, `aud`. Не логуються. Облікові дані на клієнті вимагають TLS (поза локальним демо).
5. **Авторизація.** Політика «метод → дозволені ролі». **Заборонено за замовчуванням:** метод без правила відхиляється.
6. **Покриття.** Автентифікація й авторизація застосовуються до unary і до всіх типів стрімінгових викликів.
7. **Поверхня.** Server reflection вимкнено в продакшені або захищено; повідомлення про помилки автентифікації не розкривають причину (чи підпис невірний, чи термін вийшов).
8. **Секрети.** Ключі й секрети не в репозиторії; завантаження зі сховища/змінних середовища.
9. **Негативні тести.** Побудуй матрицю й реалізуй тести.

## Обов'язкова матриця негативних тестів
| Сценарій | Очікуваний результат |
|---|---|
| Підключення без TLS до сервера з TLS | Відмова підключення |
| TLS без клієнтського сертифіката | Відмова на рукостисканні |
| Клієнтський сертифікат від стороннього CA (клієнт примусово його надсилає) | Відмова; у лозі сервера причина «невідомий CA», а не «немає сертифіката» |
| Токен відсутній | `Unauthenticated` |
| Токен із неправильним підписом / `alg=none` / протермінований / чужий `aud` | `Unauthenticated` |
| Роль без права на метод | `PermissionDenied` |
| Метод без правила в політиці | `PermissionDenied` |
| Те саме для кожного типу стрімінгу | Ті самі результати |
| Токен у логах після всіх вище перелічених тестів | Відсутній |

## Формат відповіді
1. Припущення та питання (до 5).
2. Модель загроз (таблиця).
3. Архітектура безпеки (що на якому рівні).
4. Код (конфігурація TLS, перевірка токена, інтерсептори, політика).
5. Тести за матрицею.
6. Що перевірено запуском, а що ні.
7. Рішення, які ШІ не ухвалює сам (модель довіри, джерело ідентичності, політика ротації, ролі).

## Не роби
- Не пиши власну криптографію. Використовуй перевірені бібліотеки; якщо в демо потрібна спрощена реалізація, познач це явно.
- Не вимикай перевірку сертифікатів «для зручності».
- Не залишай секрет у коді як «тимчасовий» без очевидного позначення демо.
````

## Що перевірити людині

- [ ] Усі рядки матриці негативних тестів реалізовано й проходять.
- [ ] Для сценарію «чужий CA» перевірено **лог сервера** (причина — невідомий CA), бо за замовчуванням клієнт може не надсилати такий сертифікат (див. [A #23](A-pitfalls-catalog.md)).
- [ ] Стрімінгові виклики захищені (див. [A #21](A-pitfalls-catalog.md)).
- [ ] Політика доступу справді «заборонено за замовчуванням» (додайте метод без правила і перевірте).
- [ ] У лозі й відповідях немає токенів і причин відмови автентифікації.
- [ ] Рішення про ротацію та джерело ідентичності ухвалили ви.

## Типові помилки ШІ

- TLS без вимоги клієнтського сертифіката, але з назвою «mTLS».
- Автентифікація лише для unary.
- Політика «дозволено, якщо правила немає».
- JWT без перевірки алгоритму/`exp`/`aud`.
- Негативний тест mTLS, що перевіряє лише «немає сертифіката».
- Reflection і відкритий текст «за замовчуванням» у продакшен-конфігурації.
