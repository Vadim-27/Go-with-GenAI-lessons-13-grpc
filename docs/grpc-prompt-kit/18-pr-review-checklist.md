# 18 · Рев'ю pull request (gRPC)

> **Коли:** кожна зміна, що торкається `.proto`, обробників, клієнтів, безпеки чи конфігурації.
> **Результат:** структурований перелік зауважень з пріоритетами та вердикт.
> ШІ-рев'юер — другий погляд, а не заміна людини. Найкраще працює, коли йому дають diff і контекст.

````markdown
## Чекліст
**Контракт**
- Зміни `.proto`: номери, типи, `reserved`, enum, режими стрімінгу, власні Request/Response, коментарі. Чи потрібна нова версія пакета?
- Згенеровані файли оновлено й не редаговано вручну.

**Помилки й дедлайни**
- Помилки з обробників лише через gRPC-статус із точним кодом; жодних голих помилок.
- Повідомлення без внутрішніх деталей. Дедлайни на клієнтських викликах. Ретраї лише для ідемпотентних.

**Стрімінг**
- Контекст потоку; звільнення ресурсів при виході; один відправник; `EOF` як штатне завершення; обмежені буфери; тест на скасування.

**Безпека**
- Нові методи мають правила авторизації (за замовчуванням заборонено). Стрімінгові виклики захищені. Токени не в логах. TLS не послаблено. Немає секретів у коді. Reflection не ввімкнено в продакшені.

**Продуктивність і ресурси**
- З'єднання не створюються на кожен виклик. Нема необмежених списків і повідомлень. Ліміти розміру/потоків враховано.

**Експлуатація**
- Логування без чутливих даних; метрики й health не зламано; м'яка зупинка працює; конфігурація зовнішня.

**Тести**
- Є тести на нову поведінку, на коди помилок і негативні сценарії; для стрімів — скасування й витоки; для безпеки — негативні. Тести здатні впасти.

**Залежності**
- Версії зафіксовано; немає застарілих API; плагін відповідає runtime.

## Формат відповіді
1. **Вердикт:** `можна зливати` / `зливати після правок` / `не зливати` і одне речення чому.
2. **Знахідки:** `# | рівень (Блокер / Серйозне / Мінор / Питання) | файл:рядок | проблема | чому важливо | пропонована правка`.
3. **Чого не вистачає:** тести, документація, міграційні кроки, які зміна потребує, але не містить.
4. **Що я не міг перевірити** з наданих матеріалів.
5. **Рішення, які ШІ не ухвалює сам** і які лишаються за автором та рев'юером-людиною (сумісність, ризики, компроміси).

## Не роби
- Не вигадуй проблем: кожна знахідка має посилання на місце в diff або матеріалах.
- Не пиши «загалом непогано» замість аналізу. Якщо знахідок немає, перелічи, що саме ти перевірив.
- Не пропонуй масштабних переписувань, не пов'язаних із цією зміною.
````

## Що перевірити людині

- [ ] Усі блокери та серйозні знахідки прочитано й підтверджено вручну: ШІ може помилятись у деталях.
- [ ] Знахідки мають посилання на конкретні рядки; безпідставні відкинуто.
- [ ] Результат порівняно з [A · Каталогом пасток](A-pitfalls-catalog.md): чи не пропущено щось із відомого.
- [ ] Пункт «Чого не вистачає» (особливо тести й міграційні кроки) передано автору.

## Типові помилки ШІ

- Загальні схвальні фрази без перевірки конкретних місць.
- Вигадані знахідки без прив'язки до коду.
- Не помічає відсутності, а не наявності помилок: немає stream-інтерсептора, немає правила доступу для нового методу, немає тесту на скасування.
- Пропонує переписати половину модуля замість зауважень до зміни.
