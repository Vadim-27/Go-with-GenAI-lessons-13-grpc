# 06 · Реалізація сервера

> **Коли:** є затверджений `.proto` і згенерований код.
> **Результат:** сервер із чистою архітектурою, коректними кодами помилок, м'яким завершенням і тестами.
> **Важливо:** передайте ШІ справжній згенерований інтерфейс сервера, а не лише `.proto`. Код частіше компілюється з першого разу.

## Вхідні дані

| Плейсхолдер | Що підставити |
|---|---|
| `{{PROJECT_CONTEXT}}` | Блок з [00](00-project-context.md) |
| `{{PROTO}}` | Затверджений `.proto` |
| `{{GENERATED_INTERFACE}}` | Фрагмент згенерованого інтерфейсу сервера (імена методів, сигнатури) |
| `{{DOMAIN_RULES}}` | Бізнес-правила й інваріанти (унікальність, переходи статусів, обмеження) |
| `{{STORAGE}}` | Сховище: «в пам'яті для початку» / база даних (яка) / зовнішній сервіс |
| `{{ERROR_POLICY}}` | Таблиця «помилка → код gRPC» або «запропонуй» |

## Промпт

````markdown

{{PROJECT_CONTEXT}}

## Матеріали

```proto
{{PROTO}}
```
Згенерований інтерфейс сервера:
```
{{GENERATED_INTERFACE}}
```
Бізнес-правила: {{DOMAIN_RULES}}
Сховище: {{STORAGE}}
Політика помилок: {{ERROR_POLICY}}

## Завдання
Реалізуй сервер для всіх RPC із `.proto`.

## Архітектурні вимоги
- Шари: **обробник gRPC** (тонкий: валідація входу, перетворення типів, мапінг помилок) → **сервісний/доменний шар** (бізнес-правила, без залежності від gRPC) → **репозиторій** (інтерфейс; реалізація за вибором сховища).
- Доменні помилки визначай у доменному шарі. Перетворення «доменна помилка → код gRPC» робиться в одному місці.
- Усі помилки з обробників повертай через gRPC-статус із відповідним кодом. «Голі» помилки забороняються.
- Валідуй вхід на межі: порожні обов'язкові поля, формати, діапазони → `InvalidArgument`.
- Контекст виклику передавай у сервісний і репозиторний шари; у довгих циклах перевіряй скасування.
- Не використовуй глобальний змінюваний стан. Залежності передаються конструктором.
- Для стрімінгових RPC: використовуй контекст самого потоку, гарантовано звільняй підписки/горутини при виході, `EOF` на прийманні — штатне завершення, відправляє одна горутина.
- Згенерований тип «непідтримуваного сервера» вбудуй для прямої сумісності, якщо це ідіома вашої мови.

## Вимоги до запуску
- Конфігурація (адреса, TLS, режими) через прапорці/змінні середовища.
- Запуск без TLS допустимий лише локально, і лише з явним попередженням у логу.
- М'яка зупинка за сигналом із таймаутом; після таймауту примусова зупинка (довгі стріми блокують м'яку).
- Health-сервіс. Server reflection вмикається прапорцем і за замовчуванням вимкнена поза локальною розробкою.
- Налаштуй обмеження: максимальний розмір повідомлення, число одночасних потоків, keepalive-політику (значення обґрунтуй масштабом з контексту).
- Структуровані логи; чутливі дані та токени не логуються.

## Формат відповіді
1. Припущення та питання (до 5).
2. Дерево файлів.
3. Код (повністю, без «...»), окремими блоками по файлах.
4. Таблиця «доменна помилка → код gRPC → повідомлення клієнту».
5. Як запустити й чим перевірити вручну (приклади `grpcurl`).
6. Що перевірено запуском, а що ні.
7. Рішення, які ШІ не ухвалює сам (відповідність кодів реальним збоям, політика повільних споживачів стрімів, ліміти).

## Не роби
- Не змінюй `.proto`. Якщо контракт треба змінити, запропонуй правку й зупинись.
- Не змішуй бізнес-логіку з обробниками.
- Не використовуй застарілі API бібліотеки; актуальність перевір за документацією.
- Не вигадуй залежності поза дозволеними в контексті.
````

## Що перевірити людині

- [ ] `grep` по обробниках: немає `errors.New` / `fmt.Errorf` / голих помилок у відповідях (див. [A #9](A-pitfalls-catalog.md)).
- [ ] У стрімінгових обробниках використано контекст потоку.
- [ ] Бізнес-логіка не залежить від gRPC-типів.
- [ ] Сервер справді завершується за `Ctrl+C` навіть при відкритому стрімі.
- [ ] Відповіді на негативні сценарії: невідомий id, порожній вхід, дубль, невалідний стан.
- [ ] Лог не містить токенів і персональних даних.

## Типові помилки ШІ

- Повертає звичайні помилки (клієнт отримує `Unknown`).
- Кладе бізнес-логіку прямо в обробники.
- Використовує фоновий контекст замість контексту виклику/потоку.
- Забуває м'яку зупинку або робить її без таймауту.
- Вмикає reflection і відкритий текст «за замовчуванням» без позначок.
- Використовує застарілі API з пам'яті.
