# gRPC Prompt Kit

Набір промптів для регулярної роботи з ШІ над gRPC-проєктами: від проєктування сервісу до код-рев'ю та експлуатації.
Він не прив'язаний до предметної області чи мови: проєктні деталі підставляються через `{{ПЛЕЙСХОЛДЕРИ}}`.
Основа — урок «gRPC замість REST» (Protobuf, стрімінг, автентифікація між сервісами) і досвід створення робочого демо-проєкту.

## Як користуватися

1. **Один раз на проєкт** заповніть [`00-project-context.md`](00-project-context.md). Це «паспорт» проєкту, який вставляється в кожен промпт замість `{{PROJECT_CONTEXT}}`.
2. **Постійні правила** з [`01-AGENTS-rules-grpc.md`](01-AGENTS-rules-grpc.md) покладіть у репозиторій як `AGENTS.md` / `CLAUDE.md` / `.cursorrules` (залежно від інструмента) або вставте в системний промпт чату. Тоді ШІ дотримується їх у кожній відповіді, і їх не треба повторювати.
3. **Під конкретну задачу** оберіть файл із таблиці нижче, підставте значення в `{{…}}` і надішліть блок «Промпт» ШІ.
4. **Перевірте результат** за розділом «Що перевірити людині» у тому ж файлі, а не лише «чи компілюється».

Кожен файл має однакову структуру: *коли застосовувати → вхідні дані → промпт → що перевірити людині → типові помилки ШІ*.

## П'ять принципів, на яких побудовано набір

1. **Контракт перш за все.** Спочатку `.proto`, потім код. Усе, що клієнт і сервер мають знати одне про одного, лежить в одному файлі.
2. **Явне краще за неявне.** Перелічуйте методи, патерн кожного виклику, ролі, коди помилок. Фраза «спроєктуй сервіс інвентарю» дає здогадки, а список методів дає потрібний контракт.
3. **ШІ чернетка, людина рішення.** ШІ добре пише каркас, шаблонний код та інтерсептори. Рішення про нумерацію полів, потребу стрімінгу, відповідність кодів помилок реальним збоям і наслідки зміни схеми лишаються за вами. У кожному промпті є пункт «Рішення, які ШІ не ухвалює сам».
4. **Показуйте ШІ згенероване.** Після `protoc`/`buf generate` передайте йому реальні інтерфейси. Тоді код частіше компілюється з першого разу.
5. **Перевіряйте запуском.** Усе, що ШІ стверджує («працює», «безпечно», «швидше»), перевіряється тестом, `grpcurl` або бенчмарком. У промптах є вимога позначати неперевірене.

## Поради

- **Мова.** Промпти написано українською. Ідентифікатори й API лишаються англійськими, а мову коментарів задає `{{COMMENT_LANGUAGE}}`. Якщо ваша мова не Go, ШІ має зіставити ідіоми. Деякі приклади в наборі — для Go, і це вказано.
- **Версії бібліотек.** Знання моделі про версії та API застаріває. Усі промпти просять перевіряти актуальні версії та API в офіційній документації, а не «згадувати». Якщо у вашого ШІ є пошук чи доступ до документації, увімкніть його.
- **Малі кроки.** Один промпт — одна задача й одна перевірка. Не просіть «зроби весь сервіс» одним повідомленням.
- **Скопійована відповідь не заміняє рев'ю.** Для всього, що ШІ згенерував у `.proto`, обов'язково застосовуйте [04](04-proto-review.md).
- **Копіть проблеми в набір.** Коли знайдете нову помилку ШІ, додайте її до [A · Каталогу пасток](A-pitfalls-catalog.md) і, якщо треба, до правил у `01`. Набір має еволюціонувати разом з вашою командою.

## Зв'язок із демо-проєктом до Уроку 13

Правила набору суворіші за `.proto`, показаний на слайдах і в демо `libratrack-grpc-demo`. Якщо прогнати цей `.proto` через [04 · Рев'ю .proto](04-proto-review.md), набір, найімовірніше, зробить такі зауваження:

- RPC повертають сутність `Copy` напряму, а правило набору вимагає власних `XxxResponse` (щоб запит і відповідь еволюціонували окремо);
- значення вкладеного enum названо без префікса (`AVAILABLE`, а за правилом набору `COPY_STATUS_AVAILABLE`);
- `STATUS_UNSPECIFIED` лишено всередині `Copy`, тоді як для лінтера зручніше виносити enum на верхній рівень.

Це свідомий компроміс навчального прикладу заради простоти слайдів, а не помилка набору. Для реальних проєктів дотримуйтесь правил набору.

## Статус

Набір складено на основі робочого прикладу (Go, grpc-go, grpc-gateway, buf/protoc) і типових помилок, що траплялись під час його створення. Самі промпти не прогонялись на конкретних моделях, тому перший раз спробуйте їх на невеликій задачі та підлаштуйте формулювання під ваш інструмент.
